# Перекраска CRM под нового клиента

Вся фирменная айдентика собрана в одном месте — `src/config/brand.ts`.
Чтобы получить CRM в цветах другого бизнеса, правится **только этот файл**
(и кладутся файлы логотипа в `public/`). Компоненты трогать не нужно.

## Как это устроено

```
src/config/brand.ts        ← единственный источник правды: цвета, шрифты, логотип
src/config/brand-css.ts    ← превращает конфиг в CSS-переменные (:root, .dark, акценты)
src/config/brand-fonts.ts  ← реестр шрифтов next/font
src/app/layout.tsx         ← вставляет сгенерированный CSS в разметку
```

Компоненты не содержат цветовых литералов — они читают переменные:
`style={{ color: 'var(--ink)' }}`, `background: 'var(--brand-soft)'`.
В `src/app/globals.css` определений токенов нет вообще, там только правила,
которые их потребляют.

Проверить, что правило соблюдается:

```bash
grep -rnE "#[0-9a-fA-F]{6}" src --include="*.ts" --include="*.tsx" --include="*.css" | grep -v "^src/config/"
```

Ожидаемый результат — только цвета мессенджеров в `deal-config.ts`
и зелёный пузыря WhatsApp (см. «Что намеренно осталось литералом»).

## Пошагово

### 1. Название, логотип, иконка

```ts
identity: {
  name: 'SMILEKIT',              // в сайдбаре и на экране загрузки
  shortName: 'S',                // монограмма в круглой плашке
  title: 'SMILEKIT CRM',         // <title>
  description: 'Система управления клиникой',
  tagline: 'CRM система',        // подпись под названием в сайдбаре
},
```

Логотип — файл в `public/`, плюс его «посадка» в круге:

```ts
mark: {
  image: '/logo.webp',
  position: '50% 50%',   // сдвиг картинки внутри круга
  size: '118%',          // масштаб: >100% выводит круг за края блока
  fallback: '#5115a4',   // заливка, если файл не загрузился
  shadow:      '0 5px 16px rgba(81, 21, 164, 0.34)',
  shadowLarge: '0 16px 42px rgba(81, 21, 164, 0.3)',
  focusRing:   '0 0 0 3px rgba(81, 21, 164, 0.10)',
  streamGlow:  'rgba(81, 21, 164, 0.05)',
},
```

Фавиконку заменить в `src/app/favicon.ico`.

### 2. Шрифты

```ts
fonts: { sans: 'manrope', display: 'unbounded' },
```

Доступные ключи перечислены в `src/config/brand-fonts.ts`
(`SansFontKey` — основной текст, `DisplayFontKey` — заголовки).
Нового семейства там может не быть — тогда добавьте вызов загрузчика:

```ts
// brand-fonts.ts
const unboundedDisplay = Unbounded({
  subsets: ['latin', 'cyrillic'],
  weight: ['500', '600', '700'],
  variable: '--font-display',   // ← роль задаётся именем переменной
})
```

Имя CSS-переменной фиксируется в момент вызова и потом не меняется, поэтому
реестры для текста (`--font-sans`) и заголовков (`--font-display`) разведены.
Семейство, годное в обе роли, объявляется дважды — файлы шрифта при этом
не дублируются. Новых зависимостей не требуется: всё через `next/font/google`.

### 3. Акцент

`accents` — список пресетов для переключателя в Настройках,
`defaultAccent` — какой стоит по умолчанию. Пользователь может переключить
акцент в рантайме (хранится в cookie устройства), поэтому список — часть бренда.

```ts
defaultAccent: 'smilekit',
accents: [
  {
    id: 'smilekit',
    label: 'Фиолетовый (SmileKit)',
    from:   '#5115a4',   // начало градиента
    to:     '#8a68ad',   // конец — светлый, на нём НЕЛЬЗЯ ставить белый текст
    deep:   '#360e7f',   // тёмный конец: заливки под белым текстом
    shadow: 'rgba(81, 21, 164, 0.35)',
    oklch:  '0.38 0.19 295',   // тот же цвет в oklch — для токенов shadcn
  },
  // …
]
```

> **`to` против `deep`.** Кнопки и любые заливки под белым текстом берут
> `deep`, а не `to`. У МОСТОВОГО белый на `to` (`#ff5c68`) даёт 2.84:1 —
> нечитаемо. Правило зашито в `.brand-gradient` и менять его не нужно.

`oklch` нужен, потому что компоненты `shadcn/ui` работают через `--primary`,
`--ring`, `--sidebar-primary`. Перевести hex → oklch можно любым конвертером
(например, oklch.com).

### 4. Цветовые шкалы

Секции `light` и `dark`. Для перекраски обычно достаточно двух:

```ts
brand: {
  base:   '#5115a4',   // фирменный цвет
  strong: '#360e7f',   // тёмный конец: заливки под белым текстом
  ink:    '#5115a4',   // мелкий фирменный текст (нужен контраст ≥ 4.5:1)
  soft:   '#f1ebfa',   // мягкая заливка: бейджи, аватары
  tint:   '#faf7fe',   // фон-намёк
},

neutral: {
  paper: '#faf9fc',  paperHi: '#fdfcfe',  surface: '#ffffff',
  surface2: '#f5f2fa', surface3: '#efeaf6',
  line: '#e9e4f2', lineSoft: '#ece8f4', lineMid: '#e3ddef', lineStrong: '#d8d0e6',
  ink: '#17102a', ink2: '#4e4560', ink25: '#615870', ink3: '#766d88', ink4: '#9a93a8',
  inkMuted: '#6b7280',
},
```

Нейтральную шкалу подкрашивают в тон бренду — у МОСТОВОГО она тёплая
(оттенок ~20°), у SmileKit уведена в фиолетовый (~300°). Ни один тон
не должен читаться случайным серым.

**Контраст.** `ink3` — минимальный уровень для мелкого текста (≥ 4.5:1 на
бумаге). `ink4` для текста не годится вообще — только иконки и декор.

### 5. Семантика — обычно НЕ трогают

`ok` / `warn` / `bad` / `info` при перекраске чаще всего остаются как есть:
«успех» зелёный, «ошибка» красная независимо от бренда. SmileKit оставил
`ok` и `warn` ровно такими же, как у МОСТОВОГО.

Менять их нужно в одном случае — **когда фирменный цвет конфликтует
с сигнальным**:

- У МОСТОВОГО бренд красный, поэтому ошибка обязана отличаться от него
  светлотой: `bad.ink` = `#c01818` (6.2:1) против бренда `#e11d1d` (4.8:1).
- У SmileKit бренд фиолетовый — красный освободился и целиком отдан ошибке:
  `bad.ink` = `#b91c1c`.

> **Запрещено:** бордовые, винные и марсаловые оттенки (`#7f1020`, `#9f1239`,
> `#991b1b`, `#7f1d1d`, `#a4123c`…) и тёмные почти-чёрные плашки как фон.
> Глубину дают светлотой и линиями, а не затемнением фирменного цвета.
> Два намеренных исключения — журнал событий и сайдбар, см. ниже.

### 6. Графики

```ts
charts:    { primary, secondary, positive, negative, neutral, soft },
chartText: { … те же ключи, но затемнённые двойники … },
```

Ключи названы по роли, а не по цвету — сменить палитру можно, не трогая
графики. Два требования:

1. **Серии различимы между собой** — и по тону, и по светлоте.
   «Все оттенки фирменного» нечитаемы. Держите один холодный контрапункт
   среди тёплых (у обоих брендов это зелёный).
2. **`chartText` ≥ 4.5:1 на бумаге.** Цвета заливок как текст не читаются
   (золото `#f0a52a` даёт 2.1:1), поэтому подписи, числа в таблицах и легенды
   берут затемнённых двойников того же тона.

Значения остаются literal-строками, а не `var(--…)`: Recharts не резолвит
CSS-переменные в `stop-color` градиентов на всех рендерерах.

### 7. Сайдбар и журнал событий

Обе намеренно «нетипичные» поверхности вынесены в конфиг целиком.

**Сайдбар** — у МОСТОВОГО сплошная фирменная плашка с белым текстом.
Клиент со светлым сайдбаром выражается теми же токенами:

```ts
sidebar: {
  from: '#ffffff', to: '#f5f2fa',      // светлая заливка
  foreground: '#17102a',                // тёмный текст
  activeBg: '#5115a4', activeInk: '#ffffff',
  border: 'rgba(23, 16, 42, 0.10)',
  oklch: '0.38 0.19 295',
},
```

**Журнал событий** на `/dashboard/bot-reports` — единственная намеренно
тёмная плашка: консоль и должна выглядеть как консоль. Тоже конфигурируема
(`terminal`), в том числе цвета уровней и статусов ленты лаборатории.
Светлый журнал задаётся светлым `bg` и тёмными `text` / `muted`.

### 8. Радиусы и текст на заливке

```ts
radius: '0.875rem',   // от него производятся --radius-sm … --radius-4xl
onBrand: '#ffffff',   // текст и иконки поверх фирменной заливки
```

`onBrand` — отдельный токен, а не «белый»: у клиента со светлым акцентом
читаемым будет тёмный текст.

## Осевшие оттенки (`drift`)

Секция `drift` — оттенки, накопившиеся по мере роста кода: где-то взяли
соседнюю ступень Tailwind, где-то подобрали цвет на глаз. Они сведены
в токены, чтобы перекраска не оставляла в интерфейсе чужие пятна,
и тему не различают.

При перекраске их можно оставить как есть (интерфейс будет корректным,
но кое-где сохранит исходные оттенки) либо свести к основным ступеням шкал.
**Сведение — осознанное визуальное изменение, а не механическая замена:**
делайте его отдельным шагом и просматривайте результат глазами.

То же относится к `neutral.inkMuted` — холодному серому `#6b7280`,
доставшемуся от донорского приложения и выбивающемуся из тёплой шкалы.

## Что намеренно осталось литералом

| Где | Цвета | Почему |
|-----|-------|--------|
| `components/deals/deal-config.ts` | Telegram `#0369a1`, WhatsApp `#15803d`, Instagram `#be185d`, Сайт `#0e7490` + их фоны | Фирменные цвета самих мессенджеров. Опознают источник заявки и при перекраске CRM меняться не должны. |
| `app/dashboard/consultation-chat/page.tsx` | `#dcf8c6` | Зелёный пузыря WhatsApp: переписка должна выглядеть как в мессенджере. |

Это единственные цветовые литералы вне `src/config/`.

## Проверка после перекраски

```bash
npx tsc --noEmit     # 0 ошибок
npx eslint src --quiet
```

Глазами пройти: дашборд, сделки, товары, диалоги, настройки (переключатель
акцентов), отчёты бота (тёмный журнал), экран входа. Смотреть на:

- читается ли мелкий текст (`ink3`, `chartText`, текст на фирменных заливках);
- отличается ли ошибка от фирменного цвета;
- различимы ли серии на графиках рядом друг с другом;
- не осталось ли «чужих» пятен старого бренда.
